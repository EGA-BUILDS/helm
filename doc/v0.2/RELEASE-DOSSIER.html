01The end-to-end owner journey

The product is one loop: an owner connects T3, picks how much access to grant, browses their Linear issues, launches a native worktree thread, and Helm keeps the Linear issue and the thread in step — then the owner can follow up, interrupt, bind by hand, and see whether the resulting pull request is real. Each step below is marked with what is actually proven.

  1. Owner signs in — Clerk owner grant, resolved server-side on every owner-gated call. PROVEN · CODEPENDING · NO BROWSER ORIGIN
  2. Connect T3 through native OAuth — real external OAuth, scopes read at the provider, credentials encrypted with owner+endpoint+purpose AAD. Hosted transport verified live: 83 tools with input schemas. PROVEN
  3. Choose read-only or operate access — this is the gate that made the rest of the product reachable at all; before it, no owner could ever obtain a write grant. PROVEN
  4. Connect Linear through OAuth — reading real issues across mapped projects. The Linear API is verified live on DEV; Helm's own OAuth client is the missing piece. PROVEN · APIPENDING · OAUTH
  5. Configure Linear ↔ T3 project mappings, each with the team's own started state — never a global default. PROVEN
  6. Launch a native worktree thread — one launch per attempt, durable attempt rows, a settled launch reuses its thread instead of relaunching. PROVEN PENDING · DISPATCH DISABLED ON DEV
  7. The association is recorded and the issue syncs — the exact thread is bound to the exact issue, and the issue moves to its team's In Progress state. A manual binding adopted by a later launch becomes a sync obligation again. PROVEN
  8. Follow up on the thread — one logical message carries one idempotency key; a replayed key is recognised, a receipt for another thread is refused, a stale response is discarded. PROVEN
  9. Interrupt a live run — bound to the observed run; a changed selection discards the confirmation; an unknown outcome stays ambiguous and is never retried. PROVEN
  10. Needs attention — derived from genuine run evidence, and unknown when the evidence is not decidable. Never a guess. PROVEN
  11. Link or unbind a thread by hand — for threads created outside Helm. A binding only: no status change, no launch, no Git write. PROVEN
  12. See whether the pull request is real — GitHub is the authority, the branch the thread reports is the binding, and a claim is never taken at face value. PROVENPENDING · NO GITHUB TOKEN

The code for every step is built, reviewed and integrated. The steps marked PENDING are blocked by absent DEV configuration — see owner actions — not by missing behaviour.

03Issue dossiers

What each one actually does, what review caught, and what remains unproven.

EGA-764 · native follow-up send

#18 · 6cde5b8 · 16 files · 395 backend / 310 frontend / 53 browser

Sends a follow-up to an existing thread. No launch, no re-target.

  • CAUGHTDuplicate detection was invented — assumed native markers that do not exist. Checked against the probe receipts: the envelope carries no dedupe field, and a replayed key returns the same messageId — which embeds the key, so equality is deterministic and proves nothing. Dedupe now comes only from thread reads, and reads unverified when inconclusive.
  • CAUGHTonAccepted fired on ambiguous — the mutation passed the whole suite, because the unit suite proved the helper was right and never proved the component used it.
  • CAUGHTA source-grep "queue mode" test that could not fail; deleted in favour of the behavioural assertion on the arguments actually sent.

EGA-765 · native interrupt + needs attention

#19 · 506e9f2 · 19 files · 409 backend / 308 frontend / 49 browser
  • CAUGHTA lost acknowledgement was reported as rejected — claiming no interrupt was issued when one may have been applied. Now ambiguous / dispatch_outcome_unknown, never auto-retried.
  • CAUGHTThe run-status classifier's default returned active, so an unknown status rendered as "running" and was interruptible. Now positive evidence only.
  • CAUGHTOne in-flight path rendered interrupt_requested as "Already terminal". Now reads "requested, NOT verified as terminated".
  • GAPThe confirmation reset was proven only at the pure decision layer; the lead added a browser-level suite that drives the real component.

EGA-769 · owner-selectable read-only / operate

#23 · 93acd5b · 11 files · 435 backend / 340 frontend / 57 browser

The unblocking issue. Before this, no owner could ever obtain a write grant — so launch, follow-up and interrupt were unreachable by construction.

  • CAUGHTAccessLevel said read-only | supervised | full-access while the schema and route said read-only | operate — so a real operate connection parsed to null.
  • CAUGHTThe UI never sent access, so every connection was read-only by default.
  • CAUGHTWrite controls were not permission-gated at all.
  • CAUGHTReconnect sent the form's level, not the connection's — reconnecting an operate connection asked for read-only.
  • CAUGHTThe chosen access lived in a module global and never reached the controller — partly the lead's own file-ownership rule.

EGA-766 · verified GitHub pull-request state

#24 · 61e0337 · 14 files · 443 backend / 307 frontend / 51 browser
  • CAUGHTThe first version verified a PR if it merely existed in the authorized repository: a claim of only {url, number} returned verified_open against any real PR of that number, because branch and state checks were skipped when the claim omitted them. Now the PR's head.ref must equal the thread's own branch, and a thread with no branch is thread_not_bound.
  • CAUGHTAny top-level string could be promoted into a PR claim; unknown URL fields are now inspected, never promoted.
  • CAUGHTreview_decision is not a field the REST endpoint returns — approvals could never have appeared. Replaced with a second read-only reviews call.

Disclosed limit: binding is at branch level. T3 exposes no PR id or head SHA, so two PRs from one head branch cannot be distinguished. The UI says "verified against the branch T3 reports for this thread" — never PR identity.

EGA-762 · association store + sync ledger + product trigger

#25 · 8a80f99  ·  #28 · 2f9f399 · 20 files · 406 backend
  • CAUGHTThe sync marked every association of an issue synced, including ones bound to another team — the write was right, the ledger lied.
  • CAUGHTGraphQL partial errors were checked on writes but ignored on the reads that decide to write.
  • CAUGHTA definite success:false was filed as unreachable — a network code for a refusal.
  • CAUGHTThe human-intent guard was single-shot: a third sync overwrote a state a person had deliberately set. Now sticky, direction-agnostic, and it fails closed on ambiguous baselines.
  • CAUGHTThe feature was inert — nothing called the recorder, so the table would have stayed empty forever.
  • CAUGHTThe "bounded exponential backoff" was measured to be inert: the ramp sat at the cron tick, so a failing row was hit ten times in ten minutes and a 429 row every minute — the driver sustaining the rate limiting it was clearing.
  • GAPThe two drivers could double-write for one issue; now they share one transactional in-flight claim.

EGA-763 · manual thread ↔ issue linking

#26 · 41522fa & #27 · 99c7c1 · 21 files · 428 backend / 367 frontend / 72 browser
  • CAUGHTThe launch path's thread-binding check was a windowed scan while the manual path had been fixed to an exact index. After a hundred tombstones the live row fell out of the window and a second active binding was created. Now one exact lookup, and more than one active row is a loud error.
  • CAUGHTBuilding the UI exposed a defect no backend review could see: the backend had no read path at all, so reload-recovery was impossible and the owner had no concurrency token.
  • CAUGHTThe backend's reduced shape would have made a successful read render as "could not read the current association" — a cross-lane mismatch neither side could see alone. Fixed on both sides, with a contract test.
  • GAPA manual link adopted by an accepted launch was silently never synced: adoption left the row in a state no driver owns. Now re-armed and scheduled.

EGA-770 · hosted DEV configuration + runbook

#22 · e8cb876 · 7 files · 380 backend / 284 frontend
  • CAUGHTThe validator was dead code — no caller. Then unreachable from its only caller, because it required Vercel-side variables while running on Convex. Then its leak tests were vacuous. Then its "covers every variable" claim was false by measurement — the sentinel loop short-circuited the key branch, reaching nine of twenty-two variables and none of the four encryption keys.

10Postmortem — including my own mistakes

The parts of this cycle that did not go well, recorded because they shaped the result and would otherwise be invisible.

Errors I made

  • MINEI reported a blocking defect in EGA-765 and had reproduced it in a browser — against a stale tree still holding the pre-repair component. Withdrawn, and recorded so nobody "re-fixes" a fixed defect.
  • MINEI reported a failing test that was the reviewer's live mutation, not a defect. Evidence is only as good as knowing which tree produced it.
  • MINEMy instruction to "append the marker" broke a startsWith filter and hid refused recordings. My own fix caused a regression; the review caught it.
  • MINEI forbade a lane from editing a shared file, and that file turned out to be exactly where its bug lived — the chosen access never reached the controller.
  • MINEI claimed a trigger-side test existed that did not, and I merged a docs PR before its checks finished. Both corrected.
  • PROCESSI edited the candidate worktree while a reviewer was reviewing it. The reviewer noticed, isolated a pristine checkout and measured there — the right call on their part, and mine was sloppy.

What actually caught the defects

  • Not the test suite. The three union-only defects — a read guard dead in every browser, an adopted binding silently never synced, a windowed index creating a second binding — were invisible to every per-lane suite and to every green gate.
  • Adversarial review, and specifically: mutation testing. Several "fixes" were correct in intent and unproven in effect. Three guards turned out to be unpinned — removing them changed nothing, including a backoff that was written to look bounded and measured to be inert.
  • The cumulative review of the merged tree, not the branches. Three defects existed only in the union.
  • Honest measurement. The Phase C reviewer re-ran its own round-one probes against my fixes rather than trusting them, and that is what surfaced the F3 test that passed against the very defect it named.

Decisions worth remembering

  • One shared owner per shared contract. Two lanes had each edited the same guard and each dropped the other's assertion; the fix was to make the merged guard the integration owner's single artifact, not to reconcile two weakened copies.
  • A window is never a substitute for an exact lookup. The bug class — "tombstones push the live row out of the window" — appeared twice, in two different modules.
  • When a contract is uncertain, say so in the data. unverified beats a confident duplicate; unknown beats a confident running.
  • Never merge a claim you did not measure yourself. Three times in this cycle, a green claim was wrong.
